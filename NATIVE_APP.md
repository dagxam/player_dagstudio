# DAGSTUDIO PLAYER — нативное приложение

В репозитории используется Capacitor 8. Интерфейс HTML/CSS/JS упаковывается внутрь Android/iOS-приложения, а серверные функции остаются на https://pl.dagstudio.ru.

## Что хранится внутри приложения

- интерфейс DAGSTUDIO PLAYER;
- CSS;
- JavaScript;
- изображения и иконки;
- Font Awesome.

PHP, SQLite, поиск по внешним источникам и потоковый proxy внутрь APK/IPA не копируются. Приложение обращается к production API на pl.dagstudio.ru.

## Android

Workflow **Build Android APK** автоматически собирает установочный APK и сохраняет его как GitHub Actions artifact **DAGSTUDIO-PLAYER-Android**.

Текущая автоматическая сборка — debug-signed APK, пригодный для прямой установки и тестирования на телефоне, планшете и Android-магнитоле. Для постоянных production-обновлений без переустановки нужен постоянный release keystore; его следует хранить только в GitHub Secrets, а не в репозитории.

## iPhone / iPad

Workflow **Prepare iOS App** вручную проверяет нативную iOS-сборку без подписи. Для настоящего устанавливаемого IPA потребуется Apple Developer signing certificate и provisioning profile.

## Локальная оболочка

Команда:

```bash
npm install
npm run native:web
```

создаёт папку `www/` для Capacitor. Она не коммитится в Git и пересобирается из актуальных файлов сайта.


## Офлайн-кэш музыки

Нативное приложение хранит аудио в приватной папке приложения через Capacitor Filesystem (Directory.Data) и скачивает файлы через Capacitor File Transfer.

Поведение:

- все треки, добавленные в плейлисты, ставятся в очередь локального сохранения;
- онлайн-трек после начала прослушивания также сохраняется на устройстве;
- при пропадании сети плеер автоматически использует локальную копию;
- снимок плейлистов хранится локально, поэтому ранее синхронизированные плейлисты доступны без сети;
- при удалении трека или плейлиста локальный файл удаляется, если этот же трек больше не используется в другом плейлисте;
- файлы лежат во внутреннем хранилище приложения и удаляются Android при удалении приложения.

## Обновление внутри приложения (OTA)

- Кнопка **«Обновить приложение»** обновляет веб-интерфейс, CSS и JavaScript без скачивания APK и без открытия внешнего браузера.
- Android/iOS (Capacitor): `@capgo/capacitor-updater` получает версию и SHA-256 из GitHub Release `android-web`, проверяет архив и переключает bundle с перезапуском WebView.
- Сайт и установленная PWA: Service Worker проверяет новую версию; перед перезапуском проверяется доступность сервера и сбрасывается только кэш интерфейса. Локальный кэш аудиотреков не удаляется.
- Обновления исходных нативных плагинов, Android permissions, Java/Kotlin или самого APK **не могут** устанавливаться средствами web-OTA — для таких изменений требуется новая нативная сборка.
- Чтобы новое OTA стало доступно, после коммита в `main` должен успешно завершиться workflow **Publish Android Web Update**. Один только FTP-деплой не публикует архив для нативного приложения.
- В ходе смены OTA-bundle плеер перезапускает свой интерфейс, поэтому текущее воспроизведение может прерваться. Сохранённые плейлисты и скачанные в хранилище приложения файлы остаются.



## TEYES CC3 — доработка устойчивости (октябрь 2026)

- Сохраняются позиция и отдельный список текущего воспроизведения: просмотр другого плейлиста не сбивает Next/Previous.
- После принудительного перезапуска приложение восстанавливает композицию без самопроизвольного запуска музыки. После обычного возврата в Activity повторное подключение допускается только для ранее активного воспроизведения.
- Стандартные кнопки Android Play/Pause/Next/Prev и гарнитуры обрабатываются в MediaSession; при активной Activity также работает fallback onKeyDown. Неизвестные проприетарные команды TEYES/CANBUS необходимо проверить на устройстве.
- Загружаемый аудиофайл сохраняется во временный файл; прежняя исправная версия резервируется до публикации и восстанавливается при неудачном переименовании.
- Меню кэша предоставляет ручную загрузку открытого списка, проверку записей, индикацию прогресса и очистку только аудиофайлов.
- Диагностика по запросу показывает доступность поиска у отдельных внешних источников, но не является проверкой всех аудиопотоков.
- Нативные Java-изменения требуют новой APK; OTA подходит для веб-интерфейса, но не заменяет новую нативную сборку.
