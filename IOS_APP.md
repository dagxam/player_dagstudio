# DAGSTUDIO PLAYER на iPhone

## Установка без IPA — работает сейчас

1. Откройте **https://pl.dagstudio.ru** через Safari на iPhone или iPad.
2. Нажмите системную кнопку **«Поделиться»** (квадрат со стрелкой вверх).
3. Выберите **«На экран Домой»** (Add to Home Screen); при необходимости прокрутите список действий.
4. Нажмите **«Добавить»**. Иконка DAGSTUDIO появится на домашнем экране и будет запускаться без обычной адресной строки.

В интерфейсе для iPhone появилась кнопка **«Установить на iPhone»** с инструкцией. После установки при запуске с иконки кнопка скрывается.

Это PWA, а не IPA: системная музыка, фоновое проигрывание и долговременная загрузка ограничены возможностями iOS/WebKit и конкретного аудиоисточника.

## Подготовка нативного аудио iOS

После `npx cap sync ios` запустите `node scripts/ios-prepare.mjs`: он добавляет `UIBackgroundModes=audio` и категорию `AVAudioSession.playback`, не удаляя другие фоновые режимы из `Info.plist`. Эта базовая настройка не гарантирует непрерывное воспроизведение аудио WKWebView при блокировке: нужен тест на физическом iPhone и, возможно, нативный AVPlayer с MPRemoteCommandCenter. В GitHub Actions workflow `Prepare iOS App` запускается при изменении исходников iOS/веб-оболочки или вручную и проверяет сборку симулятора **без подписи**. Это не устанавливаемый IPA.

Поскольку `DAGCarMode` и Media3 реализованы только на Android, на iOS Capacitor использует обычный HTML5-аудиоэлемент, не пытается подключить автомобильный сервис и не принимает OTA-пакеты канала `android-web`. Для нативного iPhone нужно отдельно выпускать подписанные iOS-обновления.

## Для будущей настоящей IPA

В проекте уже есть Capacitor 8 и пакет `@capacitor/ios`. На macOS с Node.js 22+ и Xcode:

```bash
npm install
npm run native:web
npx cap add ios
npx cap sync ios
node scripts/ios-prepare.mjs
npx cap open ios
```

В Xcode нужно проверить работоспособность нативных модулей на iOS (Android Media3 и автомобильные сервисы там не работают), настроить signing team и provisioning profile. После проверки можно архивировать приложение и распространять через TestFlight/App Store или другой разрешённый способ. Для обычной установки сторонней IPA необходима корректная подпись и соответствующий способ распространения. Участие в Apple Developer Program обычно требуется для TestFlight/App Store. Публиковать ключи подписи в репозитории нельзя.

Неподписанный IPA не является готовым устанавливаемым приложением. Пока нет подтверждённых данных подписи Apple, доступный пользователям способ — установка PWA через Safari.
