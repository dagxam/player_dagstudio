# Источники поиска DAGSTUDIO PLAYER

## Активные поисковые источники

В едином поиске `/api.php` (`action=search_global`) используются **только два** источника:

1. **Muzofond.fm** — `https://muzofond.fm/search/{query}?page={page}` — метка `[MUZOFOND]`.
2. **Hitmoz.org** — `https://ru.hitmoz.org/search?q={query}` — метка `[HITMOZ]`.

Оба запроса отправляются независимо и параллельно. Совпадения фильтруются по запросу, затем смешиваются в один список треков. Каждый трек содержит исходную ссылку на аудио, название, исполнителя и метку провайдера. Если один сайт недоступен, результаты второго остаются в выдаче.

**Других активных источников общего поиска нет.** Ранее подключённые провайдеры исключены из `search_global` и диагностики источников. Дополнительные серверные API-ключи не меняют состав источников.

## Статусы и диагностика

- `sources.muzo` и `sources.hitmoz` содержат ответ HTTP и количество совпадений.
- `source_counts` содержит `[MUZOFOND]` и `[HITMOZ]`.
- `has_results=true` означает совпадение по тексту, **не** подтверждённое воспроизведение.
- `audio_verified=false` сохраняется, пока аудиопоток не проверен отдельно.
- `search_complete` показывает, нужен ли повтор с более долгим ожиданием. После полного прохода он `true`.
- Кнопка «Проверить источники» отображает только два активных источника и проверяет доступность найденного аудио при подходящих условиях подключения.

## Ограничения проверки

Изменения внесены в GitHub, но проверить доступность поиска и реальное воспроизведение на `pl.dagstudio.ru`, в России и на Android/TEYES CC3 можно только после развёртывания на рабочий PHP-сервер и тестирования на устройстве. Внешние поисковые страницы могут возвращать 403, перенаправления, изменять HTML или не отдавать прямые аудиоссылки. Ни один источник не объявляется постоянно работающим без проверки.

Сохранённые пользовательские плейлисты и общий механизм воспроизведения не удаляются. Их старые записи могут сохранять ссылки на другие домены, но эти домены больше не используются для **нового поиска**.

## Попытка подключения ru.hitmos.site — 25.11.2026

По просьбе владельца проверен `https://ru.hitmos.site/` как замена ранее недоступного Hitmoz. GitHub Actions получил HTTP 403 на главной странице и на четырёх вариантах поискового URL. Пробное подключение поиска с PHP-сервера `pl.dagstudio.ru` дало HTTP 0 и ноль совпадений; одновременно Muzofond вернул 25 треков по запросу Miyagi, и воспроизведение через прокси было проверено.

**Решение:** не считать `ru.hitmos.site` рабочим источником и вернуть предыдущий код, чтобы не менять выдачу и пользовательские плейлисты на основании непроверенной гипотезы. Для реализации нужны разрешённый серверный поиск, подтверждённый формат выдачи и доступный аудиопоток. HTTP-статус сам по себе не подтверждает наличие прав на ретрансляцию аудио.
