# Музыкальные источники DAGSTUDIO PLAYER

## Доступность в России
Все запросы поиска и официальной ленты Audius идут через API проекта
https://pl.dagstudio.ru. Android-клиент использует проверенный HTTPS fallback
при DNS-сбое для домена DAGSTUDIO. Это НЕ гарантия доставки музыки от любого
внешнего поставщика: каталог может вернуть HTTP 403/404, региональное ограничение,
либо временно быть недоступным для сервера.

## Подключение музыки
- Audius: официальный API, поиск, новые релизы, популярное; резервный
  публичный адрес discoveryprovider.audius.co. Воспроизведение использует
  разрешённые публичные stream URL, с TLS и проверкой сервера.
- Jamendo: необязательный 8-й источник (Creative Commons). Требует **свой**
  JAMENDO_CLIENT_ID (переменная окружения PHP на сервере). Не используйте
  открытый тестовый client_id из документации в production. Стримы принимаются
  только с HTTPS storage.jamendo.com и дочерних хостов; для песен Jamendo
  в интерфейсе отображается источник и ссылка на CC-лицензию.
  Скачивание треков Jamendo в этой версии отключено: наличие stream URL
  не означает разрешение download.
- SoundCloud: официальный каталог-переход, пока нет зарегистрированного
  API-приложения и соответствующего лицензированного потока.
- MusicBrainz: каталог-переход и проверка дискографии; это НЕ хранилище
  аудиозаписей. Для API нужен User-Agent и лимит 1 запрос в секунду.
- Звук-М и Kavkaz Music: переход к премьерам и архивам на сайтах
  издателей. Не использовать их веб-страницы как незаявленные MP3 API:
  для встроенного проигрывания нужны условия лицензирования/API.
- Кавказ Хит: ссылка на официальный радиоэфир. Встраивание/ретрансляция
  возможна только при разрешении радиостанции.

## Проверки перед отметкой "Работает"
1. API возвращает matching_tracks > 0 для конкретного запроса.
2. HEAD запрос к прокси отвечает 200/206 с audio/*.
3. Устройство реально проигрывает больше 30 секунд без внезапного пропуска.
4. Тест в России без VPN через мобильного оператора и TEYES CC3.
5. Повторный запуск из кэша; перемотка через HTTP Range.

Мониторинг: GitHub Actions / Music Source Health — каждые 6 часов.
Тесты не утверждают доступности всех семи/восьми источников. Встроенное
воспроизведение SoundCloud, каталогов правообладателей и MusicBrainz не
заявляется до реализации согласованного и проверенного API.


## Проверка на 18 ноября 2026 года
- Hitmos.fm — **отдельный сайт**, не Hitmoz.org. Публичная главная
  может перенаправлять на rus.hitmos.fm, но это не API.
  Встроенный источник HITMOS доступен **только** после получения от
  оператора законного HTTPS JSON-эндпоинта и проверки аудиопотоков.
  Отсутствие настройки показывается как `configured=false`, не как HTTP 200.
- Для русских и кавказских новинок GitHub Actions проверяет несколько
  поисковых фраз и конкретных исполнителей отдельно от общей фразы Miyagi.
  HTTP 200 с нулём совпадений не считается рабочим поисковым источником.
- Для точной сортировки в плеере **проверенные даты** сравниваются до дня.
  Треки без даты идут ниже, а одинаковые даты допускают чередование

- Данные о новых кавказских релизах можно сверять с официальными страницами
  https://kavkazmusic.tv/category/premery и
  https://zvuk-m.com/muzykalnye-premery. Это источники **метаданных и ссылок**:
  автоматическое аудиовоспроизведение требует разрешения правообладателя.


## Hitmos в общем поиске DAGSTUDIO

Источник Hitmos.fm участвует в **общем** `search_global` (не отдельная вкладка),
когда оператор предоставил разрешённый API и домены лицензированного аудио.
Настройка сервера PHP:

- `HITMOS_SEARCH_API_URL=https://authorized-provider.example/api/search`
- `HITMOS_AUDIO_HOSTS=cdn1.example.org,cdn2.example.org`

Адреса выше — примеры формата, не рабочие URL Hitmos.
API принимает параметры `q` и `page` и отвечает JSON вида:
`{"tracks":[{"title":"...","artist":"...","audio_url":"https://cdn1.example.org/track.mp3","release_date":"2026-11-18"}]}`.

Аудиодомены должны быть перечислены по одному, без шаблонов и IP.
Прокси разрешает HTTPS аудио Hitmos **только** на этих точных доменах,
не следует перенаправлениям на другие хосты и проверяет Content-Type.
При отсутствии API или списка доменов диагностический статус —
`configured=false`, не ложные результаты поиска. Доступность главной
страницы Hitmos не подтверждает ни API, ни право на ретрансляцию музыки.


## Openverse (без ключа, общий поиск)
Openverse — официальный поисковый API открыто лицензированных аудиозаписей.
Источник участвует в общем search_global и диагностике. Для безопасного
воспроизведения принимаются только прямые аудиофайлы с
https://upload.wikimedia.org/wikipedia/commons/, содержащие лицензию
CC0, Public Domain Mark или CC BY с проверяемой ссылкой на Creative Commons.
Исполнитель, страница оригинала и лицензия показываются в списке поиска.
Остальные хосты, неподходящие записи и аудиофайлы с сомнительными
лицензиями пропускаются. Номер даты индексации никогда не используется
как дата релиза. Офлайн-скачивание из этого источника отключено.
Это не обещание наличия свежих российских или кавказских хитов:
результаты и совместимость аудиофайлов проверяются отдельно.


### Результаты прямой проверки 18.11.2026
Music Source Health #96: Openverse вернул HTTP 200, однако
по запросам Russian folk, Caucasus music и Dagestan не было
ни одной подтверждённой аудиозаписи. Встроенный поиск также
не получил совпадений. Поэтому источник по умолчанию отключён
и не замедляет поиск. Для повторного эксперимента на PHP-сервере
можно установить DAG_OPENVERSE_ENABLED=1, предварительно проверив
условия открытых лицензий и реальные воспроизводимые файлы.
